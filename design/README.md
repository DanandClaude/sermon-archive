# Design reference

These four files are the UI mockup for the web app, exported from the design canvas. Treat them as a **visual and content reference**, not production code.

| File | Screen |
|---|---|
| `1-upload.dc.html` | Contributor upload: drop zone, tape details, processing queue |
| `2-library.dc.html` | Sermon library: search, filters, status tabs, table with summary line |
| `3-review-sermon.dc.html` | Review a sermon: original vs cleaned audio, scripture references (editable), transcript, summary, details, what happens on approve |
| `4-admin-connections.dc.html` | Admin: shared drive, admin backup vault, YouTube, podcast, publishing rules, team, activity |

How to read them
- Every style is inline, so exact colors, sizes, spacing and copy can be read straight from the markup. Tokens are summarized in `SPEC.md` §16.
- They use a custom wrapper (`<x-dc>`, `<helmet>`, `<sc-for>`) from the design tool. Ignore those tags; the HTML inside is ordinary. The waveform bars are generated by a small script at the bottom of `3-review-sermon.dc.html`.
- Rebuild each screen as real components in the chosen framework and use real data. Don't copy the markup wholesale.
- All names, sermons, dates and durations are fictional sample data.
- Screens not yet designed are listed in `SPEC.md` §10.
